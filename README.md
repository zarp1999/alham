# Alham

登録不要、端末内保存の習慣アプリ。React Native / Expo / TypeScript / SQLite。

## 起動

Node.jsとnpmを用意して、このフォルダーで実行します。

```powershell
npm ci
npm run android
```

Android StudioのDevice Managerで仮想端末を起動しておいてください。SDKの場所が自動検出されない場合：

```powershell
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
$env:Path += ";$env:ANDROID_HOME\platform-tools;$env:ANDROID_HOME\emulator"
npm run android
```

Expo GoはプロジェクトのExpo SDKと互換性のあるものが必要です。CLIが案内するエミュレーター用バージョンを使用してください。
Macでは同じリポジトリを取得し `npm ci` → `npm run ios` で確認します（Xcodeとシミュレーターが必要）。
node_modulesはパソコン間でコピーしません。

## 実装済み

- 初回案内、今日、習慣一覧、追加／編集、詳細カレンダー、振り返り、設定
- 毎日／曜日指定／週N回、カテゴリー、小さな実行目標
- 達成・休み・取消、過去の記録修正、休止・再開
- SQLiteへの即時保存。アプリの再起動後も保存
- JSONバックアップの書き出し／復元と入力検証、復元直前の自動退避

週は月曜始まり。１日１習慣につき１回まで。週N回の習慣は週内のどの日でも選べるよう毎日ホームに表示します。
休みは達成数に加算しません。頻度変更は当日から適用し、過去の設定履歴を保存します。
初期版は達成回数を表示し、予定日に対する達成率は計算しません。

端末テスト：習慣作成→達成→アプリを終了→再起動→記録保持、取消、休み、日付変更、頻度編集、休止／再開、バックアップ復元。

## 初期版の範囲

通知、タイマー、ウィジェット、テーマ切り替え、並べ替え、アーカイブ、ストア公開設定は今後追加。
ローカル保存は暗号化データベースではありません。書き出したJSONにも記録が含まれます。
自動クラウド同期は行いません。機種変更やアンインストール前に、バックアップを別の場所に保存してください。
開発時はMetroが必要です。PCなしのオフライン動作は、配布用ビルドでも確認してください。

## 2026-10-21 動作確認

画面遷移はExpo Router、共有データはsrc/store.tsxで管理します。
npm run android はSDKの標準保存先を検出し、Androidからの接続を転送してExpoを起動します。
先にDevice Managerで仮想端末を起動してください。開発サーバーを終了するときはCtrl+Cです。

Android（Pixel 10a / Expo Go）で以下を実際に確認しました。
- 達成→休み→取り消し。休みは達成数に含まれません。
- 毎日から週３回への編集。過去の達成記録が残ります。
- 休止／再開、詳細／編集からのAndroidの戻る操作。
- 端末のDocumentsにJSONを書き出し、選択して復元。直前データの退避も成功。
- アプリの強制終了後の起動で記録を保持。

Androidのバックアップは保存先フォルダーを選択します。端末ルートやDownloadのルートを選べない場合はDocuments内のフォルダーを使ってください。
Androidの読み込みはシステムのファイル選択で許可したURIを直接読みます（Expo GoのDocumentPickerキャッシュと新File APIの読み取り互換性の問題を回避）。
iOSのファイル共有・復元はMacBookまたは実機で今後確認してください。

検証：TypeScript、ESLint、日付・頻度・重複記録・バックアップ検証の５テスト、Expo Doctor 20/20、Android/iOSのJSバンドル生成。

## 質問から習慣を見つける（2026-10-21追加）

習慣がまだない状態で起動すると、ホームの代わりに `/discover` を開きます。
「変えたいこと → 使える時間 → 候補 → 名前・目標・頻度の確認」の４段階で１件登録します。
「まだ決まっていない」では全候補を表示し、「自分で決める」では自由入力できます。
初回の習慣と案内完了フラグは同じSQLiteトランザクションで保存します。
途中でアプリを終了した場合、未登録の回答は保存せず、次の起動で最初から案内します。
既存の習慣がある方はホームから始まり、「習慣」タブの「質問に答えて習慣を見つける」で追加できます。
回答は端末内の候補選択にのみ使います。AI通信やオンラインサーバーは不要です。
今回の質問画面は型チェック・Lint・既存５テストで確認。画面操作の実機確認は未実施です。

## 習慣ごとの時刻通知

登録・編集画面の「時刻を決めてお知らせ」をONにすると、通知の許可を確認し、24時間表記で時刻を設定できます。初回質問画面の最後にも同じ設定があります。
- 毎日：毎日設定時刻に通知。曜日指定：その曜日だけ通知。
- 週○回：曜日が決まっていないため毎日通知（画面にも明示）。達成済みの日も通知。
- 休止・通知OFF・時刻や曜日の変更・バックアップ復元時に予約を更新。
- 設定画面の「５秒後にテスト通知を送る」で通知を確認できます。
- 通知音を使うリマインダーです。鳴り続ける目覚ましではありません。マナーモード・集中モード・電池節約などのOS設定に従い、時刻の厳密な保証はしません。
- 通知予約エラーや権限拒否は画面に表示。予約は最大60件（曜日指定は曜日ごとに１件）。古いバックアップも読み込めます。

SDK 58のexpo-notifications 58.1.5はルートimportでExpo GoにないTopicSubscriptionModuleを読み込むため、src/local-notifications.tsでローカル通知のサブパスimportを集約しています。パッケージ更新時にこの互換対応を再確認してください。サーバー接続・Push Token取得は使いません。

Expo Goの通知チャンネル作成にもネイティブ側の互換問題があったため、Expo Goでは標準チャンネルを使用し、独立したアプリでは「習慣のリマインダー」チャンネルを作成します。Expo Goの判定にはexpoGoConfigを使用します（開発ビルドとは区別）。
今回の確認：型チェック・Lint・７テストに成功。Androidエミュレーターでアプリ起動と設定画面、通知許可ダイアログの表示を確認。実際の配信確認にはダイアログでAllowを押す必要があります。iOS実機・独立したアプリでの通知配信は未検証です。

### 2026-10-22 Android通知の動作確認
Pixel 10a / Expo Goで、ユーザーによる通知許可後、５秒後のテスト通知が画面上部に表示され、Androidの通知一覧にも日本語タイトル・本文が登録されることを確認しました。
既存の「本を読む」でリマインダーをONにし、20:00を保存しました。Androidの予約一覧に20:00の通知が登録されていることも確認しました。週３回の習慣のため、案内どおり毎日20:00に通知する設定です。実際の音の聴取とiOS実機検証は未実施です。
追記：アプリを終了して開き直した後も、ホームの「本を読む」に「通知 20:00」が表示されることを確認しました。

### 2026-10-22 質問形式の登録画面の改善
時間は選択式から分単位の自由入力に変更しました（全角数字対応）。入力した時間を候補の実行目標に反映します。
取り組むペースは毎日・曜日指定（複数選択）・週1〜7回に対応。曜日未選択での保存を防ぎ、既存の曜日別通知予約にも連携します。
端末内保存・サーバー送信の有無などの画面上の説明を削除しました。バックアップ操作に必要な説明は残しています。
